# Shared Video Pipeline — Team Protocol

## Purpose

All teammates use the same video-processing implementation and settings.
The pipeline extracts facial blendshapes, head pose and an experimental RGB
trace. These features are not distress labels.

## Fixed configuration

- Pipeline entry point: `ubfc_pipeline/team_runner.py`
- Stage 1 implementation: `ubfc_pipeline/s1_video_ts.py`
- Face model: `models/face_landmarker.task`
- Landmark sampling stride: 3 frames
- Window duration for downstream processing: 30 seconds
- Window stride for downstream processing: 10 seconds
- Smoke test: first 600 frames
- Default mode: rPPG enabled
- Do not change feature definitions or thresholds independently.

## Input requirements

The current inventory expects filenames in this format:

- `vid_s1_T1.avi`
- `bvp_s1_T1.csv`
- `eda_s1_T1.csv`

The subject and task IDs must match across modalities when physiological
signals are being paired with video.

The current runner selects recordings by subject ID. Assign different
subject IDs to teammates where possible to avoid duplicate processing.

## Setup

1. Clone or obtain the same repository revision.
2. Create/use the project's `video_venv`.
3. Install the dependencies listed in `ubfc_pipeline/requirements.txt`.
4. Obtain the official MediaPipe `face_landmarker.task` model and place it at
   `models/face_landmarker.task`.
5. Keep raw videos and physiological data in approved local storage; do not
   commit raw data to GitHub.

Use the same Python environment, dependency versions, model file and code
revision across teammates.

## Smoke test

From the project root:

    source video_venv/bin/activate

    python ubfc_pipeline/team_runner.py \
      --root data/ubfc_phys_subset \
      --out ubfc_pipeline/out/TEAM_smoke \
      --model models/face_landmarker.task \
      --stride 3 \
      --subjects 1 \
      --limit-frames 600

Use a new output directory for every run. The runner refuses to reuse
existing expected NPZ outputs.

## Full processing

Replace the root, output directory and subject ID with the assigned values:

    python ubfc_pipeline/team_runner.py \
      --root /path/to/dataset \
      --out /path/to/unique_output_directory \
      --model models/face_landmarker.task \
      --stride 3 \
      --subjects 2

Do not run full-length recordings until the 600-frame smoke test passes.

## Expected outputs

Each run produces:

- `s<subject>_T<task>.npz`: Stage 1 time-series arrays
- `manifest.csv`: source paths and processing configuration
- `qc.csv`: structural checks and quality warnings
- `run_metadata.json`: run settings and elapsed time

Keep these outputs together. Do not rename feature columns or manually edit
the generated NPZ/CSV files.

## Acceptance checks

Before submitting a run, verify:

1. `structural_status` is `PASS`.
2. Face-valid fraction is inspected; a high value does not prove correct
   facial tracking.
3. Missing values and QC warnings are reviewed.
4. Timestamps are increasing and spacing checks pass.
5. RGB trace is present when rPPG is enabled.
6. The run used the agreed model, stride and code revision.

A structural PASS does not validate rPPG accuracy, distress labels, or
generalization to unseen participants.

## Handoff

For each assigned recording, submit:

- The generated manifest and QC report
- Run metadata
- The NPZ output through approved project storage
- Any warnings or failures and a brief note about them

Do not submit raw video or physiological data through public GitHub.

## Current limitations

- The runner currently selects recordings by subject ID, not an arbitrary
  individual video path.
- Window-level features are generated by Stage 2, not by Stage 1.
- rPPG is experimental and must not be treated as validated heart rate.
- No distress labels should be inferred from facial expressions.
- Keep all recordings from one participant together when creating
  participant-independent training, validation and test splits.
